# Architecture Decision Records (ADR)

Ce dossier consigne les décisions d'architecture et d'organisation structurantes du dépôt **neoxix-soc-academy**, ainsi que leur justification.

## Pourquoi des ADR

Un portfolio technique évolue sur plusieurs mois. Les ADR permettent de retracer *pourquoi* une décision a été prise (structure de dossiers, conventions de nommage, choix d'outillage) sans devoir reconstituer le contexte à partir de l'historique Git seul.

## Convention de nommage

```
NNNN-titre-court-en-kebab-case.md
```

Exemple : `0001-structure-des-domaines-pedagogiques.md`

## Statuts possibles

| Statut | Signification |
| --- | --- |
| Proposed | Décision proposée, pas encore actée |
| Accepted | Décision actée et appliquée |
| Superseded | Remplacée par une décision ultérieure (référencer le nouvel ADR) |
| Deprecated | Abandonnée sans remplacement direct |

## Modèle minimal d'un ADR

```markdown
# NNNN - Titre de la décision

## Statut
Accepted

## Contexte
Quel problème ou quelle question a motivé cette décision ?

## Décision
Que décide-t-on précisément ?

## Conséquences
Quels sont les impacts, compromis ou travaux futurs induits ?
```
